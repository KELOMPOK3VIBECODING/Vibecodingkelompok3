# Code Review Log — API Perpustakaan Terintegrasi

**Proyek:** API Perpustakaan Terintegrasi  
**Teknologi:** Laravel, PHP, MySQL, Laravel Sanctum  
**Tujuan:** Mencatat hasil pemeriksaan kode backend dan tindak lanjut yang disarankan.

| No. | Bagian yang direview                                       | Temuan                                                                                                                                                                                                                                                                                   | Perbaikan/Keputusan                                                                                                                                                                                                                                                              | Status                           |
| --- | ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------- |
| 1   | `app/Http/Controllers/AuthController.php` — `login()`      | Password dibandingkan secara langsung menggunakan `$user->password !== $request->password`. Ini menunjukkan password disimpan/diperiksa dalam bentuk teks biasa, bukan melalui hash password. Jika database bocor, password pengguna dapat terbaca.                                      | Ubah penyimpanan password menjadi hash menggunakan `Hash::make()` dan verifikasi login dengan `Hash::check()`. Pastikan data akun uji di database juga diubah menjadi hash sebelum perubahan diterapkan. Setelah itu, uji login berhasil dan login dengan password salah.        | Perlu diperbaiki dan diuji ulang |
| 2   | `app/Http/Controllers/LoanController.php` — `store()`      | Pengecekan ketersediaan buku, pengecekan batas tiga pinjaman aktif, pembuatan transaksi, dan perubahan `is_available` dilakukan tanpa transaksi database atau penguncian baris. Dua request bersamaan berpotensi sama-sama lolos pengecekan dan membuat data peminjaman tidak konsisten. | Bungkus proses peminjaman dalam `DB::transaction()` dan pertimbangkan `lockForUpdate()` pada baris buku serta pengecekan pinjaman aktif agar pemeriksaan dan perubahan data berlangsung secara konsisten. Uji peminjaman normal, buku tidak tersedia, dan batas tiga buku aktif. | Perlu diperbaiki dan diuji ulang |
| 3   | `app/Http/Controllers/LoanController.php` — `returnBook()` | Endpoint mengubah status transaksi menjadi `dikembalikan` lalu mengubah buku menjadi tersedia. Proses ini belum dibungkus transaksi database; jika salah satu penyimpanan gagal, status transaksi dan ketersediaan buku bisa tidak sinkron.                                              | Bungkus pembaruan transaksi dan buku dalam `DB::transaction()`. Pertahankan pemeriksaan transaksi tidak ditemukan dan transaksi yang sudah dikembalikan. Uji pengembalian berhasil, ID transaksi tidak ditemukan, dan pengembalian ulang.                                        | Perlu diperbaiki dan diuji ulang |

## Ringkasan

Pemeriksaan menemukan tiga area yang perlu ditindaklanjuti: keamanan penyimpanan password, konsistensi proses peminjaman, dan konsistensi proses pengembalian. Temuan ini didasarkan pada kode yang diperiksa, bukan hasil pengujian runtime. Perbaikan harus diterapkan dan diuji sebelum statusnya diubah menjadi selesai.
